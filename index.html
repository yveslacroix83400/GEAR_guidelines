1. How an agent actually works

A chatbot mainly generates text. An agent adds a controlled action loop around a model.

1. User goal
2. Model reasons
3. Selects tool
4. Tool executes
5. Result returns
6. Agent answers
M

Model

Interprets the request and decides what to say or which tool to call. It does not magically access your files, database or the web.

I

Instructions

Define role, boundaries, workflow and output expectations. Good instructions say when to use a tool and when to ask for confirmation.

T

Tools

Normal functions or services exposed to the agent. A tool should have a clear name, typed parameters, a precise docstring and structured return value.

S

Session & state

The session groups one conversation. State stores working values such as a selected customer, intermediate result or workflow status.

R

Runner

Coordinates messages, model calls, tool calls, events and session services. It is the runtime loop around the agent.

G

Guardrails

Validation, permissions, confirmation gates, timeouts and logging. Use deterministic code for critical rules, not prompting alone.

Practical rule: give the model judgment; give tools actions; give code hard constraints. For payments, deletion, email sending or data changes, require explicit confirmation and enforce authorization outside the prompt.

3. Build a first useful ADK agent

From the workspace root, scaffold the package:

adk create my_agent

Then replace my_agent/agent.py with this small tool-using agent:

from datetime import datetime
from zoneinfo import ZoneInfo
from google.adk.agents import Agent


def get_local_time(timezone: str) -> dict:
    """Return the current local time for an IANA timezone, e.g. Europe/Paris."""
    try:
        now = datetime.now(ZoneInfo(timezone))
        return {"status": "success", "timezone": timezone,
                "local_time": now.isoformat(timespec="minutes")}
    except Exception:
        return {"status": "error", "message": "Use an IANA timezone such as Europe/Paris."}


root_agent = Agent(
    name="course_helper",
    model="gemini-flash-latest",
    description="A practical assistant that can look up local time.",
    instruction=(
        "Answer concisely. Use get_local_time whenever a user asks for "
        "the current time. Never invent a tool result."
    ),
    tools=[get_local_time],
)

Create my_agent/.env:

GOOGLE_API_KEY="paste_your_ai_studio_key_here"

Smoke test:

adk run my_agent

5. Tools, state and memory

Write tools that agents can use reliably

  • Use a verb-based name: search_catalog, not catalog.
  • Type every parameter and explain formats in the docstring.
  • Return JSON-like dictionaries with status, data and a safe error message.
  • Validate inputs inside the tool. The model is not your security boundary.
  • Keep side effects separate from read-only tools.
  • Add timeouts and retries to network tools.

Know the three kinds of context

Conversation

Messages currently visible to the model. Long histories cost tokens and may need summarisation.

Session state

Structured working data shared during the current workflow. Useful for passing outputs between sub-agents.

Long-term memory

Information retrieved across sessions. It needs explicit storage, retrieval rules, access control and deletion policies.

6. Orchestrate agents without creating chaos

Start with one agent. Split it only when roles, permissions, tools or evaluation criteria are genuinely different.

PatternUse it whenExampleMain risk
LLM delegationThe route depends on meaning and judgment.Coordinator transfers to billing, technical support or sales.Wrong routing. Give descriptions and explicit transfer rules.
SequentialAgentSteps must run in order.Extract requirements → draft → compliance review.Error propagation. Validate each intermediate output.
ParallelAgentTasks are independent.Research pricing, competitors and regulations simultaneously.Cost and rate limits. Cap concurrency.
LoopAgentIterative maker-checker improvement is useful.Writer revises until reviewer accepts.Infinite loops. Set a maximum iteration count and exit condition.

A simple sequential pattern

from google.adk.agents import Agent, SequentialAgent

researcher = Agent(
    name="researcher",
    model="gemini-flash-latest",
    instruction="Collect the facts needed for the brief.",
    output_key="research_notes",
)

writer = Agent(
    name="writer",
    model="gemini-flash-latest",
    instruction="Write a concise brief using {research_notes}.",
    output_key="draft",
)

root_agent = SequentialAgent(
    name="brief_pipeline",
    sub_agents=[researcher, writer],
)
Evaluation tip: test both the final answer and the trajectory: which agent was selected, which tool was called, with which arguments, and whether the workflow stopped correctly.

7. Use the Google AI Studio Gemini API

Google AI Studio ↗ is the quickest way to obtain a Gemini API key for local learning and prototypes. ADK reads GOOGLE_API_KEY; the standalone Google Gen AI SDK commonly reads GEMINI_API_KEY. Keep the variable name required by the library you are actually using.

Direct Gemini API call, without ADK

pip install -U google-genai
# .env
GEMINI_API_KEY="your_key_here"
from dotenv import load_dotenv
from google import genai

load_dotenv()
client = genai.Client()  # reads GEMINI_API_KEY
response = client.models.generate_content(
    model="gemini-flash-latest",
    contents="Explain tool calling in three bullet points.",
)
print(response.text)

When to use which

Google Gen AI SDK

Use for direct model calls: text, images, structured output, embeddings or function calling managed by your own code.

ADK

Use when you need agents, sessions, tools, workflow orchestration, traces, evaluation and deployment patterns.

Vertex AI / Google Cloud

Use for enterprise IAM, project governance, production controls and managed deployment. Prefer Application Default Credentials or service identity in production.

8. .env files and secret safety

A public GitHub repository is the wrong place for API keys. A deleted commit may still exist in Git history, forks, caches and logs.

Safe local pattern

# .gitignore
.venv/
__pycache__/
*.py[cod]
.env
**/.env
!.env.example
.vscode/settings.json
# .env.example — safe to commit
GOOGLE_API_KEY="replace_me"
# or, for the standalone Google Gen AI SDK:
GEMINI_API_KEY="replace_me"
  • Commit .env.example, never the real .env.
  • Check before every push: git status and git diff --cached.
  • For GitHub Actions, use Repository → Settings → Secrets and variables → Actions.
  • For Cloud Run, use Secret Manager and grant the runtime service account only the secret-access role it needs.
  • Use separate keys for development and production; restrict keys and monitor usage/quota.
If a key is exposed: revoke or rotate it immediately, then inspect usage and billing. Removing the text from the latest commit is not enough. Treat the key as compromised.

Production authentication

Do not copy a personal key into a container image. On Google Cloud, prefer a dedicated service account and Application Default Credentials. Apply least privilege, avoid long-lived service-account key files, and inject configuration at runtime.

9. From local prototype to public service

  1. Local: test with adk run and adk web.
  2. Integration: use adk api_server; add authentication before exposing anything publicly.
  3. Evaluation: create representative prompts, expected tool calls and failure cases.
  4. Cloud: deploy to Cloud Run or an appropriate managed Agent Runtime.
  5. Operations: add logs, traces, budgets, rate limits, alerting, timeout policy and secret rotation.
Cloud Run is a practical course target: it runs a containerized service, scales with requests and integrates with IAM, Cloud Logging and Secret Manager. It is billable, so set budgets and remove test resources when finished.

Public frontend warning

GitHub Pages is static. Never place a Gemini key in browser JavaScript. Put the key in a protected backend such as Cloud Run, then let the web page call that backend. Add authentication, restrictive CORS, request validation and abuse controls.

10. Debugging checklist

Import error

Confirm VS Code uses .venv. Run python -m pip show google-adk in the same terminal.

Agent not found

Run ADK from the parent folder. Confirm the package contains __init__.py and agent.py exposes root_agent.

Authentication error

Check the variable name, location of .env, key restrictions and whether the shell inherited the variable.

Tool never called

Improve the tool name, type hints and docstring. Tell the agent exactly when it must use the tool.

Looping agent

Add maximum iterations, a clear completion signal and a fallback to a human.

Works locally, fails in cloud

Check runtime identity, secrets, enabled APIs, region, port binding, dependencies and timeout limits.

Glossary

ADK
Google's open-source Agent Development Kit for building, running, evaluating and deploying agents.
Agent
A model-driven component with instructions and optional tools that acts toward a goal.
A2A
Agent2Agent protocol for communication and collaboration between agents.
API
A defined interface through which software sends requests and receives responses.
Callback
Code invoked at a defined point in the agent lifecycle for control, logging or validation.
Context window
The amount of input and history a model can process in one request.
Event
A runtime record such as a user message, model output, tool request or tool result.
Function calling
The model produces structured arguments for a function; your runtime executes it.
Guardrail
A deterministic or model-assisted control that checks inputs, outputs or actions.
IAM
Identity and Access Management: who can do what on which cloud resource.
LLM
Large language model used for understanding, generation and action selection.
MCP
Model Context Protocol, a standard way to expose tools and context to AI applications.
Orchestration
Coordination of agents and steps using delegation, sequential, parallel, loop or graph patterns.
RAG
Retrieval-augmented generation: retrieve relevant sources before generating an answer.
Runner
The runtime component that executes an agent and coordinates events and services.
Session
A bounded interaction thread linking a user, an agent, events and state.
State
Structured working values available during an agent session or workflow.
Tool
A callable capability such as a Python function, API, search service or database query.
Trace
A record of execution steps used to inspect latency, routing, model and tool calls.
Vertex AI
Google Cloud's managed AI platform for enterprise model access, governance and operations.
